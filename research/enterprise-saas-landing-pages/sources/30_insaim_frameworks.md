## Verbatim Quotes

### Framework Selection by Product Type
> **Jobs-To-Be-Done (JTBD) framework** — "best for productivity tools like Notion, ClickUp, and Miro"
> **Cybersecurity, enterprise infrastructure, compliance, and complex HealthTech products** — "live here by necessity. The visitor arrives skeptical and accountable to others. A demo-first page won't move them — they need a case built incrementally."
> **When to use it:** "enterprise SaaS, long sales cycles, regulated industries."
> **Limitation:** "the longest path to conversion — not suitable for products where visitors should self-serve immediately."

### Awareness Ladder Framework
> "The default pattern for most SaaS products, and for good reason. Every screen answers exactly one question. The visitor is never asked to hold multiple ideas simultaneously — they're walked through a sequence where each section resolves and sets up the next."
> "Linear, Vanta, and Mercury all use this pattern."
> "If a section doesn't resolve something or raise a new question, it breaks the chain."

### Narrative Scroll Pattern (Problem-First)
> "Snyk.io SaaS landing page using narrative scroll pattern — problem-aware hero section with outcome metrics and product UI for B2B security software"
> "The most durable B2B pattern. The page opens on the pain, lets it breathe, then introduces the product as the resolution."
> "Problem-first is the natural execution pattern for PSP and Awareness Ladder frameworks. It gives the problem enough space to create genuine tension before the solution appears."
> "HealthTech, compliance, and enterprise products use this because their buyers arrive with the problem already present — they don't need to be told they have it, they need to see that someone understands it well enough to solve it."

### Demo-First Pattern
> "Spiral.ad SaaS landing page using demo-first scroll pattern — product interface leading the page for a mobile app creative engine"
> "It fails when the product requires context to appreciate — which describes most B2B SaaS. Applying a demo-first pattern to a product with a complex workflow or an abstract value proposition is one of the most common structural mistakes in startup landing page design."

### Category Creation Pattern
> "Gong.io SaaS landing page using category creation scroll pattern — Revenue AI OS positioning across CRO, RevOps, and sales team use cases"

## Analysis Notes

**Validates H4:** Enterprise SaaS (legal tech = compliance/regulated) requires **Awareness Ladder** or **Problem-First/Narrative Scroll** pattern — not Demo-First. Dealenz currently uses a hybrid Advantage-tab approach that may not build the case incrementally enough.

**Validates H5:** "Cybersecurity, enterprise infrastructure, compliance, and complex HealthTech products... need a case built incrementally" — legal tech/contract intelligence falls in this category. The page must answer buyer questions sequentially, building trust before showing product.

**Key Insight:** Linear (developer tool) uses Awareness Ladder. Gong (category creation) uses Category Creation. Legal tech should use Problem-First/Narrative Scroll because buyers are "skeptical and accountable to others."
